# SPEC-007: スキップ開始・未確定案件管理

## 概要
案件選択画面（W-02）に担当現場が登録されていない場合、作業員が案件情報なしで現場開始できる（スキップ開始）。
スキップ開始された場合、管理者のダッシュボード（A-01）に「案件情報未確定」として表示され、
管理者が後から正しい案件を紐付ける。
作業員には入力を求めない（外国人作業員の負荷を考慮し、2タップで現場開始できる設計）。

## 対応画面
- W-02: 案件選択画面（[現場が一覧にない] ボタン）
- W-01: 打刻画面（スキップ開始後のステータス表示）
- A-01: 管理ダッシュボード（未確定案件の一覧表示・紐付け）

## 対応ユースケース・ルール
- UC-10: 未確定案件を紐付ける
- 境界コンテキスト「現場管理」ルール#14, #15

## 受入基準

### W-02: スキップ開始（作業員側）
- [ ] [現場が一覧にない] ボタンが案件一覧の下部に表示される
- [ ] ボタンをタップすると確認ダイアログが表示される
- [ ] 確認ダイアログに入力欄はない（作業員は何も入力しない）
- [ ] 確認ダイアログで [はい] をタップすると、案件情報なしで現場開始が記録される
- [ ] 確認ダイアログで [いいえ] をタップすると、ダイアログが閉じてW-02に戻る
- [ ] スキップ開始後、W-01に戻りステータスが「現場作業中（案件情報未確定）」になる
- [ ] スキップ開始の打刻にはジョブIDが紐付かない（jobId = null）

### W-01: スキップ開始後の表示
- [ ] ステータス表示が「現場作業中（案件情報未確定）」となる
- [ ] 通常の現場作業中と同様に [現場終了] ボタンが使える
- [ ] 現場終了後の作業報告の促しも通常通り表示される
- [ ] 作業報告（W-03）の案件名は「未確定」と表示される

### A-01: 未確定案件の一覧表示（管理者側）
- [ ] スキップ開始された案件がある場合、管理タブに「案件情報未確定」一覧が表示される
- [ ] 各未確定案件に作業員名、現場開始日時が表示される
- [ ] 未確定案件がない場合は一覧が非表示になる
- [ ] 未確定案件をタップすると紐付けモーダルが表示される

### A-01: 未確定案件の紐付け（管理者側）
- [ ] 紐付けモーダルに既存の案件一覧が表示される
- [ ] 案件を検索できる（物件名・住所で検索）
- [ ] 既存の案件を選択して [紐付け] で案件を紐付けられる
- [ ] [＋ 新規案件として登録] で新規案件を作成して紐付けられる
- [ ] 紐付け完了後、「案件情報未確定」一覧から該当項目が消える
- [ ] 紐付け完了後、該当の打刻記録・作業報告に正しい案件情報が反映される
- [ ] [キャンセル] でモーダルを閉じる（未確定のまま残る）

## 操作フロー

### スキップ開始（W-02 正常系）

| # | ユーザー操作 | システム動作 |
|---|------------|------------|
| 1 | W-02で [現場が一覧にない] をタップ | — |
| 2 | — | 確認ダイアログを表示:「現場が一覧にありませんか？案件情報なしで作業を開始します。」 |
| 3 | [はい] をタップ | — |
| 4 | — | TimeStamp { type: 'SiteStart', time: now(), jobId: null } を保存 |
| 5 | — | DailyRecord.status を 'onSite' に更新 |
| 6 | — | UnconfirmedJob レコードを作成 |
| 7 | — | W-01に戻り、ステータスを「現場作業中（案件情報未確定）」に更新 |

### 未確定案件の紐付け（A-01 正常系）

| # | ユーザー操作 | システム動作 |
|---|------------|------------|
| 1 | A-01の「案件情報未確定」一覧の項目をタップ | — |
| 2 | — | 紐付けモーダルを表示（案件一覧＋検索） |
| 3 | 案件を検索・選択 | — |
| 4 | [紐付け] をタップ | — |
| 5 | — | UnconfirmedJob.jobId を選択した案件のIDに更新 |
| 6 | — | 関連する TimeStamp, WorkReport の jobId を更新 |
| 7 | — | モーダルを閉じ、未確定一覧から該当項目を削除 |

## エラーハンドリング

| 条件 | 動作 | メッセージ |
|------|------|-----------|
| 未出勤でスキップ開始 | [現場が一覧にない] 非活性（SPEC-003と同様、現場開始自体が不可） | — |
| 紐付け先の案件が見つからない | [＋ 新規案件として登録] で新規作成を促す | 「該当する案件が見つかりません」 |
| 紐付け処理の保存失敗 | エラー表示、再試行可能 | 「保存に失敗しました。再度お試しください」 |

## データモデル

```javascript
// 未確定案件
UnconfirmedJob {
  unconfirmedId: string,      // 未確定案件ID（自動生成）
  workerId: string,           // スキップ開始した作業員のID
  workerName: string,         // 作業員名（表示用）
  siteStartAt: datetime,      // 現場開始日時
  siteEndAt: datetime | null, // 現場終了日時（終了前はnull）
  jobId: string | null,       // 紐付け先の案件ID（紐付け前はnull）
  resolvedAt: datetime | null // 紐付け完了日時（未解決はnull）
}

// SPEC-003で定義済みの TimeStamp を拡張
// jobId が null の場合 = スキップ開始による打刻
TimeStamp {
  // ...既存フィールド
  jobId: string | null        // null = 案件情報未確定
}
```

## UI仕様

### W-02: スキップ確認ダイアログ
- **メッセージ**: 「現場が一覧にありませんか？案件情報なしで作業を開始します。」
- **ボタン**: [いいえ]（左） / [はい]（右）
- **入力欄なし**（作業員の負荷を最小化）

### A-01: 未確定案件一覧（管理タブ内）
- 未読バナーと作業員一覧の間に表示
- 各項目: `⚠️ 案件情報未確定 — 田中太郎 08/05 09:30`
- タップで紐付けモーダルを開く
- 未確定案件がない場合は非表示

### A-01: 紐付けモーダル
- **ヘッダー**: 「案件を紐付け」タイトル
- **対象表示**: 「田中太郎 / 08/05 09:30 の現場作業」
- **検索**: 物件名・住所で検索
- **案件一覧**: 検索結果の案件カード（物件名＋住所）
- **フッター**: [＋ 新規案件として登録] / [キャンセル]
- 案件選択時: [紐付け] ボタンが表示される
